# note-ios

iOS client for **Pingolin Note** — end-to-end encrypted notes. SwiftUI, Swift
5.9, deployment target iOS 17.0. The Xcode project is generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from
[`project.yml`](project.yml) and is not committed.

Notes are encrypted on the device. The server stores ciphertext and never sees
note content or key material.

## Repository layout

| Path | What it is |
|---|---|
| `App/` | The app: `Views/`, `Managers/`, `Services/`, `Local/` (encrypted offline cache), `Configuration.swift`. |
| `Shared/` | Sources compiled into the app *and* both extensions. |
| `NoteShareExt/` | Share-sheet extension (`com.pingolin.note.share`). |
| `NoteWidgets/` | Widget extension (`com.pingolin.note.widgets`). |
| `Sources/PingolinNoteSDK/` | Generated UniFFI Swift bindings. **Committed**, but machine-generated — regenerated by `build-ios.sh` whenever the SDK changes. Don't hand-edit. |
| `lib/PingolinFFI.xcframework` | The Rust core as a binary framework. **Built, not committed** — see below. |
| `Tests/NoteTests/`, `Tests/NoteUITests/` | Unit and UI test targets. |

## Prerequisites

- **Xcode 26.0** (`project.yml` sets `xcodeVersion: "26.0"`). Full Xcode, not
  just the command-line tools — `build-ios.sh` calls `xcodebuild
  -create-xcframework`.
- **XcodeGen** — generates `Note.xcodeproj`.
- **Rust** (via rustup) with the three iOS targets.
- **protoc** — the Rust build needs it on `PATH`.

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
brew install xcodegen protobuf
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios
```

## Sibling checkouts

The Rust core is not in this repository. Two sibling checkouts are required
next to this one:

```
<parent>/
├── note-ios-public/   ← this repository
├── mobile-sdk/        ← crates/mobile-sdk + crates/note-collab-sdk
└── pingolin-crypto/   ← the crypto core
```

Clone the two siblings under exactly those names; the relative paths depend on them:

```sh
git clone https://github.com/pingolindev/mobile-sdk-public.git mobile-sdk
git clone https://github.com/pingolindev/pingolin-crypto-public.git pingolin-crypto
```

`pingolin-crypto` must sit **beside** `mobile-sdk`, not inside it, because
`mobile-sdk/crates/mobile-sdk/Cargo.toml` depends on it by relative path:

```toml
pingolin-crypto = { path = "../../../pingolin-crypto" }
```

## Building the XCFramework

`lib/` is gitignored, so the framework does not arrive with a clone — you build
it. [`build-ios.sh`](build-ios.sh) compiles both Rust crates for device and
simulator, generates the Swift bindings, and combines everything into a single
`lib/PingolinFFI.xcframework`.

It requires **one of two** environment variables, and fails immediately without
them:

```bash
if [[ -z "${MOBILE_SDK_SRC:-}" && -z "${MOBILE_SDK_REPO:-}" ]]; then
  echo "error: set MOBILE_SDK_REPO (workspace root) or MOBILE_SDK_SRC (single-crate path)." >&2
  exit 64
fi
```

- **`MOBILE_SDK_REPO`** — preferred. The `mobile-sdk` **workspace root**. Both
  crates are resolved from it.
- **`MOBILE_SDK_SRC`** — back-compat. Path to the single `mobile-sdk` crate
  (`<repo>/crates/mobile-sdk`); the workspace root is derived from it.

Two optional overrides, both defaulted:

- `NOTE_COLLAB_SDK_SRC` — defaults to `$MOBILE_SDK_REPO/crates/note-collab-sdk`.
- `STAGING` — scratch directory for intermediate artifacts, defaults to
  `$HOME/staging`.

```bash
MOBILE_SDK_REPO=../mobile-sdk ./build-ios.sh
```

Why one combined framework rather than two: SPM will not accept two binary
targets that each ship a `Headers/module.modulemap`, since they collide on the
same output path. The script `libtool`s the two static archives together and
writes a merged modulemap declaring both the `pingolin_mobileFFI` and
`collabFFI` modules.

## Generate the project and build

`xcodegen generate` must run before you open anything — `Note.xcodeproj` does
not exist in a fresh clone.

```bash
xcodegen generate
MOBILE_SDK_REPO=../mobile-sdk ./build-ios.sh
open Note.xcodeproj
```

Or from the command line:

```bash
xcodebuild -project Note.xcodeproj -scheme Note \
    -destination 'platform=iOS Simulator,name=iPhone 17' build
```

## Tests

`NoteTests` is offline and needs no configuration:

```bash
xcodebuild -project Note.xcodeproj -scheme Note \
    -destination 'platform=iOS Simulator,name=iPhone 17' test
```

## Environments

`AppEnvironment` has exactly three cases — **there is no staging environment**:

```swift
enum AppEnvironment: String, CaseIterable {
    case production
    case development
    case local
```

| Environment | Auth API | Note API | Web |
|---|---|---|---|
| `production` | `api-auth.pingolin.com` | `api-note.pingolin.com` | `note.pingolin.com` |
| `development` | `api-auth.pingolindev.com` | `api-note.pingolindev.com` | `note.pingolindev.com` |
| `local` | `localhost:8081` | `localhost:8090` | `localhost:3000` |

DEBUG builds default to `.development` and RELEASE builds to `.production`. In a
DEBUG build the choice can be overridden at runtime through the `UserDefaults`
key `app_environment`.

## Contributing and security

This repository is published as one snapshot per release: each commit is a
shipped version, tagged with it, and the tree at a tag is the source that
version was built from. Development happens elsewhere, so this repository
takes no pull requests or issues.

Report security problems by email to **security@mail.pingolin.com**, not in
public.
